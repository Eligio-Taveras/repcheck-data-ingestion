# 7.5 Amendment Text Availability Checker

> Part of [Component 7 — Amendments Pipeline](../07-AMENDMENTS-PIPELINE.md)

## Why amendments need their own text path

Amendments can substantively alter the function of a bill or the resulting law — a single substitute amendment ("in the nature of a substitute") can replace the entire body of a bill while leaving the bill number and metadata intact. Analysis that reads only the *finalized amended bill text* sees the outcome but misses the per-amendment contribution: which provisions did each individual amendment add, strike, or reword? For scoring legislators on amendment-specific votes (a common case — many high-profile votes are on amendments, not on final passage), the analysis pipeline needs the amendment's own text, not just the bill's.

This area + §7.6 brings amendment text into the system as a first-class entity, mirroring the existing two-pipeline split for bill text:

| Bill side (existing) | Amendment side (this area + §7.6) |
|---|---|
| `bill-text-availability-checker` polls `/bill/.../text`, picks canonical version, emits `bill.text.available` | `amendment-text-availability-checker` (§7.5) — same shape against `/amendment/.../text` |
| `bill-text-pipeline` consumes event, downloads, extracts, chunks, embeds | `amendment-text-pipeline` (§7.6) — same shape, no govinfo mirror, HTML/PDF only |

## Overview

**Cron-scheduled Cloud Run Job.** Mirror of [`bill-text-availability-checker`](../../../../bill-text-availability-checker/) — runs on Ofelia/Cloud-Scheduler tick, queries `amendments` table for candidates needing a text check, calls `/amendment/{congress}/{type}/{number}/text` for each, picks the canonical version, compares against `amendment_text_versions`, and emits `amendment.text.available` for any new version. Records `last_text_check_at` and `text_versions_count` on the amendments row for state tracking.

```
Cloud Scheduler (Ofelia tick — every 4 hours)
    |
    v
amendment-text-availability-checker (one-shot Cloud Run Job)
    |
    +-- amendmentRepo.findCandidatesForTextCheck(minCongress=117, staleAfter=4h)
    |     filters: amendments.congress >= 117
    |              AND amendmentType != SUAMDT  (SUAMDT is 97th-98th only — no modern text)
    |              AND (last_text_check_at IS NULL OR last_text_check_at < NOW() - staleAfter)
    |
    +-- For each candidate (parEvalMap config.parallelism):
          +-- generate correlationId = UUID.randomUUID() per amendment
          +-- GET /amendment/{c}/{type}/{n}/text  (using AmendmentTextApiClient)
          +-- AmendmentTextVersionSelector.selectAllNewVersions(textVersions[], existing) -> List[(version, format)]
          +-- For each new (version, format) tuple:
          |     emit AmendmentTextAvailableEvent on amendment.text.available topic
          +-- ON SUCCESS ONLY (per L1):
                amendmentRepo.updateLastTextCheckAt(amendmentId)
                Sets last_text_check_at = NOW()
          +-- ON FAILURE: do NOT update last_text_check_at — next cron tick retries
```

> **Trigger model — cron-scheduled, mirroring `bill-text-availability-checker` exactly.** Earlier drafts attempted an event-driven model subscribing to a `amendment.metadata.ingested` event from §7.3. **Reverted** to cron because the bill-text-availability-checker is cron-driven and we mirror that pattern (per Q10). The cron model is also self-healing: if a previous run crashed or the Pub/Sub publisher had an outage, the next cron tick re-discovers stale candidates and proceeds. No event redrive logic needed.

## Classes

### `AmendmentTextApiClient[F[_]: Async]`

Extends `CongressGovPaginatedClient[F, AmendmentTextItemDTO]` for the `/amendment/.../text` endpoint. Mirror of [`BillTextApiClient`](../../../../bill-text-availability-checker/src/main/scala/repcheck/ingestion/bills/textcheck/api/BillTextApiClient.scala).

| Function | Signature | Behavior |
|---|---|---|
| `fetchTextVersions` | `(congress: Int, amendmentType: AmendmentType, number: String) => F[List[AmendmentTextItemDTO]]` | GET `{baseUrl}/amendment/{congress}/{lowercase-type}/{number}/text?api_key=…&format=json`. Decode `{textVersions: [...], pagination: {count}}`. Wrap with `RetryWrapper` + `AmendmentTextApiErrorClassifier` (cause-chain walk for `EmberException`/`IOException`, same shape as §7.1). HTTP 404 → log info + return empty list (amendment has no text granules — common for House amendments per upstream docs). HTTP error → `AmendmentTextCheckFailed`. |

### `AmendmentTextItemDTO` (in shared-models)

```
final case class AmendmentTextItemDTO(
  `type`:    Option[String],          // "Submitted", "Modified" — Senate only emits these forms today
  date:      Option[String],          // ISO-8601 datetime as raw string — parsed downstream by §7.5 (matches P7.0 contract)
  formats:   List[AmendmentFormatDTO]
)

final case class AmendmentFormatDTO(
  `type`: String,                     // "PDF" | "HTML" — XML/Formatted Text not documented for amendments
  url:    String                      // typically www.congress.gov — see §7.6 download path
)
```

### `AmendmentTextVersionSelector` (object)

Selects every new (version, format) tuple to emit events for. **Per Q8 — emit events for ALL new versions, not just the latest canonical** (Submitted + any subsequent Modified both get ingested as historical evidence trail).

```scala
object AmendmentTextVersionSelector {
  // Format priority — HTML preferred over PDF because extraction is lossless
  // for HTML; PDF requires the existing PdfStreamExtractor and is lossier.
  // No XML entry — amendments don't have Formatted XML granules per upstream docs.
  private val FormatPriority: Map[String, Int] = Map(
    "HTML" -> 0,
    "PDF"  -> 1,
  )
}
```

> **Per S6 simplification — no `selectCanonical` method.** Earlier drafts had both `selectCanonical` (returning a single best version+format) and `selectAllNewVersions` (returning all new tuples). Q8 mandated the latter; the former became dead code. Removed.

| Function | Signature | Behavior |
|---|---|---|
| `selectAllNewVersions` | `(versions: List[AmendmentTextItemDTO], existing: List[AmendmentTextVersionDO]) => List[(AmendmentTextItemDTO, AmendmentFormatDTO)]` | (1) For each upstream version, derive (versionTypeCode, formatType) tuple. (2) Filter to versions with at least one supported format. (3) Within each, pick the highest-priority format (HTML over PDF). (4) Subtract any already-ingested (versionTypeCode, formatType) pairs from `existing`. (5) Return remaining tuples. Emits one `amendment.text.available` event per returned tuple. |
| `versionTypeCode` | `(rawType: Option[String]) => Option[String]` | Map upstream `type` strings to short codes for the new `amendment_text_version_code_type` enum (per L3 — distinct from bill-side `text_version_code_type`). Initial mapping: `"Submitted" -> "SUB"`, `"Modified" -> "MOD"`. Unknown types return `None` (caller skips). |

### `AmendmentTextAvailabilityChecker[F[_]: Async]`

The pipeline body. Constructor: `(amendmentRepo, amendmentTextApiClient, amendmentTextVersionRepository, eventPublisher, config, logger, xa)`.

| Function | Signature | Behavior |
|---|---|---|
| `streamAll` | `(runId: UUID) => Stream[F, ProcessingResult]` | Mirror of [`BillTextAvailabilityChecker.streamAll`](../../../../bill-text-availability-checker/src/main/scala/repcheck/ingestion/bills/textcheck/pipeline/BillTextAvailabilityChecker.scala). Query candidates via `amendmentRepo.findCandidatesForTextCheck(minCongress=117, staleAfter=config.checkLookbackHours)` — the SQL pre-filter excludes pre-117th and SUAMDT directly so the per-candidate filter doesn't have to. `parEvalMap(config.parallelism)` over each. Per amendment: generate `correlationId = UUID.randomUUID()`; call `processAmendment`. |
| `processAmendment` (private) | `(amendment: AmendmentDO, correlationId: UUID) => F[ProcessingResult]` | (1) `apiClient.fetchTextVersions(amendment.congress, amendment.amendmentType, amendment.number)` returns ALL versions (Submitted + any subsequent Modified). (2) `existing <- amendmentTextVersionRepository.findByAmendmentId(amendment.amendmentId)`. (3) `selector.selectAllNewVersions(versions, existing)` returns the diff. (4) For each new (version, format) tuple: emit one `AmendmentTextAvailableEvent` carrying `amendment.amendmentId`, `amendment.naturalKey`, plus version+format details. (5) **On success only** (per L1) — `amendmentRepo.updateLastTextCheckAt(amendment.amendmentId)` updates `last_text_check_at = NOW()`. (6) Return `Succeeded` if any events emitted, `Skipped("all-versions-already-ingested")` if none new, `Skipped("no-supported-format")` if upstream returned nothing usable. **Failure path: any exception from the API call, the publisher, or the timestamp UPDATE leaves `last_text_check_at` unchanged so the next cron tick retries.** |

### `AmendmentTextAvailableEvent` (in pipeline-models)

```
final case class AmendmentTextAvailableEvent(
  amendmentId:     Long,              // surrogate id from amendments.id (per Q3)
  naturalKey:      String,            // {congress}-{type}-{number}
  congress:        Int,
  amendmentType:   AmendmentType,     // SAMDT | HAMDT | SUAMDT
  number:          String,
  versionTypeCode: String,            // "SUB" | "MOD"
  formatType:      String,            // "HTML" | "PDF"
  url:             String,            // download URL (www.congress.gov CREC URL — §7.6 rewrites to api.govinfo.gov)
  publishedDate:   Option[Instant],
  correlationId:   UUID
)
```

Pub/Sub topic: `amendment.text.available`. Added to pipeline-models per [P7.5](PRODUCTION_TASKS.md).

### `AmendmentTextCheckerApp` (IOApp)

Pure wiring. **One-shot Cloud Run Job** — runs, processes all candidates, exits (mirrors [`BillTextCheckerApp`](../../../../bill-text-availability-checker/src/main/scala/repcheck/ingestion/bills/textcheck/app/BillTextCheckerApp.scala) exactly). Loads `AppConfig`, builds resources via `Resource.use`, constructs the checker, runs the stream to completion, returns `ExitCode.Success` or `ExitCode.Error`. Triggered by Ofelia/Cloud Scheduler on a 4-hour cron tick.

### Error types

Per Q10 of planning, §7.5 has its **own dedicated error types and classifier** with distinct names from §7.1's. Both call sites hit `api.congress.gov` but the failure modes are scoped differently — §7.1 is the metadata fetch path, §7.5 is the text-availability poll path. Distinct names make stack traces and observability counters unambiguous about which call site failed.

```
final case class AmendmentTextCheckFailed(
  amendmentId: Long,
  naturalKey: String,
  endpoint: String,
  statusCode: Option[Int],
  detail: String,
  cause: Throwable = null
) extends Exception(s"Amendment text check failed [$naturalKey@$endpoint]: $detail", cause)

final case class AmendmentTextCheckHttpError(statusCode: Int, body: String) extends HttpStatusError(statusCode, body)

object AmendmentTextCheckErrorClassifier
  extends HttpStatusErrorClassifier[AmendmentTextCheckHttpError](
    transientStatusCodes = Set(429, 500, 502, 503, 504)
  ) {

  override def classify(error: Throwable): ErrorClass =
    if (isTransientNetworkError(error)) ErrorClass.Transient
    else super.classify(error)

  // Same cause-chain walk as AmendmentsApiErrorClassifier (§7.1) — duplicated intentionally per Q10.
  // If a third call-site needs this pattern, extract a shared helper at that point.
  @tailrec
  private def isTransientNetworkError(t: Throwable, depth: Int = 0): Boolean = …
}
```

**Differences from §7.1's classifier:**
- Different concrete `HttpStatusError` subclass (`AmendmentTextCheckHttpError` vs `AmendmentsApiHttpError`) so the type-system distinguishes them.
- 404 on `/amendment/.../text` is logged at info level and treated as Systemic-but-skip (amendment has no text — common, expected for many House amendments). 404 on §7.1's detail endpoint is also Systemic-but-skip but for different reasons (amendment withdrawn). Counters are distinct: `amendment_text_check_404_total` vs `amendment_fetch_404_total`.
- Network-level failures (`EmberException` mid-page, `IOException`) classified as Transient via the shared cause-chain walk pattern. Same logic, separate class.

## Schema additions to `amendments` table

Per S2 simplification, only **one** new column plus an index — `text_versions_count` was dropped (the count is derived from `amendment_text_versions` directly when needed):

| Column | Type | Purpose |
|--------|------|---------|
| `last_text_check_at` | `TIMESTAMPTZ` (nullable) | RepCheck-internal — when `amendment-text-availability-checker` last successfully completed text check for this amendment. NULL until first successful check. **Set only on success** (per L1) — failure path leaves it unchanged so the next cron tick retries. **Excluded from `ChangeDetector`** per §7.2 Date Semantics. |

Index: `CREATE INDEX amendments_text_check_pending_idx ON amendments (last_text_check_at NULLS FIRST) WHERE congress >= 117;` — partial index supports the candidate query without scanning pre-117th rows.

`AmendmentRepository` (§7.2) gains two text-related methods:

```scala
def findCandidatesForTextCheck(minCongress: Int, staleAfter: FiniteDuration): F[List[AmendmentDO]]
def updateLastTextCheckAt(amendmentId: Long): F[Unit]
```

`amendmentId` here is the surrogate `Long` (per Q3). `updateLastTextCheckAt` sets `last_text_check_at = NOW()` and is called **only on the success path** of `processAmendment` (per L1). The candidate query SQL (parameterized — `staleAfter` passed as a parameter, never interpolated, to avoid the SQL-injection risk flagged in earlier drafts):

```sql
SELECT id, natural_key, congress, … (full AmendmentDO columns)
FROM amendments
WHERE congress >= ?
  AND amendment_type != 'SUAMDT'
  AND (last_text_check_at IS NULL OR last_text_check_at < NOW() - ?::interval)
ORDER BY last_text_check_at NULLS FIRST
LIMIT ?
```

## Coverage Limits — Documented Realities

Per [LoC AmendmentEndpoint.md](https://github.com/LibraryOfCongress/api.congress.gov/blob/main/Documentation/AmendmentEndpoint.md):

| Population | Text availability |
|-----------|-------------------|
| **Senate submitted amendments, 117th Congress forward (2021+)** | Full text granules — searchable on Congress.gov, served by `/text` endpoint |
| **House amendments, 117th Congress forward** | Partial — *"Not all House amendments have text granules available"* per upstream |
| **Either chamber, pre-117th Congress** | No structured granules — only links to Congressional Record (which we do not ingest) |
| **SUAMDT** (Senate unprinted) | 97th-98th Congresses only per upstream — therefore no text endpoint coverage in modern API |

Practical implication: **the candidate query filters `congress >= 117`**, and the per-amendment processor accepts `Skipped("no-supported-format")` as a normal outcome for many House amendments and any pre-117th carryover. This is not a failure; it's the upstream coverage shape. The `last_text_check_at` column prevents re-polling the same no-text amendment on every run.

## Acceptance Criteria

| Criterion | Test |
|-----------|------|
| Candidate query excludes pre-117th amendments | Insert amendments at congresses 116, 117, 118 → `findCandidatesForTextCheck` returns only 117 + 118 |
| Candidate query excludes SUAMDT | Insert SAMDT, HAMDT, SUAMDT in congress 117 → returns only SAMDT and HAMDT |
| Candidate query selects amendments never checked | Row with `last_text_check_at IS NULL` → returned |
| Candidate query selects amendments stale beyond `staleAfter` | Row with `last_text_check_at = NOW() - 8h`, `staleAfter = 4h` → returned |
| Candidate query excludes recently-checked amendments | Row with `last_text_check_at = NOW() - 1h`, `staleAfter = 4h` → not returned |
| Per-amendment correlation ID is fresh per run | N candidates → N distinct UUIDs in event payloads |
| `fetchTextVersions` 404 returns empty list, no exception | Mock 404 → `Right(List.empty)` |
| `selectAllNewVersions` prefers HTML over PDF within each version | Single version with both formats → returns the HTML format |
| `selectAllNewVersions` falls back to PDF when HTML absent | Single version, PDF only → returns the PDF format |
| `selectAllNewVersions` skips versions with only unsupported formats | Version with format `"XML"` only → omitted from result |
| `selectAllNewVersions` returns BOTH Submitted and Modified when both are new | Upstream returns SUB + MOD, neither in `existing` → returns 2 tuples |
| `selectAllNewVersions` filters out already-ingested tuples | `existing` contains (SUB, HTML) → upstream's (SUB, HTML) is filtered, but (MOD, HTML) is returned |
| `versionTypeCode("Submitted")` → `Some("SUB")` | Direct test |
| `versionTypeCode("Modified")` → `Some("MOD")` | Direct test |
| `versionTypeCode("UnknownType")` → `None` | Direct test |
| Already-ingested version does not emit a duplicate event | Insert matching row in `amendment_text_versions` → `Skipped("already-ingested")`, no event emitted |
| New version emits `AmendmentTextAvailableEvent` with correct payload | Mock API → spy publisher → assert event fields match expected DTO + URL |
| **`last_text_check_at` updated only on successful API + publish + UPDATE path** (per L1) | Run pipeline against successful API response → `last_text_check_at = NOW()`. Run pipeline against API that 5xx-fails → `last_text_check_at` UNCHANGED (next cron tick retries). Run pipeline where publisher throws → `last_text_check_at` UNCHANGED. |
| **`last_text_check_at` retries are bounded only by `staleAfter`** | Force a candidate to fail the API call. Re-run before `staleAfter` elapses → candidate is NOT re-tried (last_text_check_at hasn't advanced, but staleAfter window blocks re-selection)? **Wrong** — staleAfter compares NOW() to last_text_check_at; if last_text_check_at IS NULL (never succeeded), the candidate is always selected → re-tried every cron tick. Test asserts: failure-only history → candidate selected on every cron tick until success. |
| **No `text_versions_count` column on `amendments`** (per S2 simplification) | `\d amendments` shows no `text_versions_count` column. The candidate query and any "fresh-versions-available" check derive count from `count(*) FROM amendment_text_versions WHERE amendment_id = ?` directly. |
| Per-amendment correlation ID is fresh per run | N candidates → N distinct UUIDs in event payloads |
| Pre-117th amendments never trigger a `/text` call | Insert congress 115 amendments → spy API not invoked even if directly asked |
| `EmberException` (mid-page socket close) treated as Transient | Inject EmberException → retry → succeeds |
