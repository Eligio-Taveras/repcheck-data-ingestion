# 7.2 Amendment Repository

> Part of [Component 7 — Amendments Pipeline](../07-AMENDMENTS-PIPELINE.md)

## Overview

Doobie repository for the `amendments` table. Simple upsert on natural key — no history archival, no child tables. Uses `UpsertHelper` from `ingestion-common` (Component 3 §3.5) for SQL generation.

All table and column names come from `Tables.*` constants in `pipeline-models` (Component 2). `AmendmentDO` comes from `shared-models` (Component 1 §1.2).

## Classes

### `AmendmentRepository[F[_]]` — Trait + Impl

```
trait AmendmentRepository[F[_]] extends EntityRepository[F, AmendmentDO] {
  def upsert(amendment: AmendmentDO): F[AmendmentDO]                  // RETURNING-style: returns the persisted DO with surrogate id
  def upsertPlaceholder(naturalKey: String): F[Unit]                  // idempotent insert; caller does findByNaturalKey separately to get id (mirrors BillRepository.upsertPlaceholder)
  def findById(id: Long): F[Option[AmendmentDO]]
  def findByNaturalKey(naturalKey: String): F[Option[AmendmentDO]]

  // Per P2 — batch variant for the change-detector pre-filter, called once per list page
  // to avoid N round-trips when reconciling page items against stored rows.
  def findByNaturalKeys(naturalKeys: List[String]): F[Map[String, AmendmentDO]]

  // bill_id is the RESOLVED ancestor bill (set inline by the §7.3 processor at ingest time, walking the
  // parentAmendmentId chain). For top-level amendments: bill_id = direct upstream bill.
  // For sub-amendments: bill_id = ancestor bill found by walking parents. NULL only for legitimate
  // orphans (procedural / treaty amendments with no bill anywhere in the chain).
  // Per 2026-05-05 review: no separate `effectiveBillId` column — `billId` carries this semantic.
  def findByBillId(billId: Long): F[List[AmendmentDO]]                // returns all amendments whose resolved ancestor is $billId
  def findByCongress(congress: Int): F[List[AmendmentDO]]
  def findByParentAmendmentId(parentId: Long): F[List[AmendmentDO]]

  def insertIfNotExists(entity: AmendmentDO): F[Unit]                   // from EntityRepository

  // Used by §7.5 amendment-text-availability-checker (cron-driven, per Q10)
  def findCandidatesForTextCheck(minCongress: Int, staleAfter: FiniteDuration): F[List[AmendmentDO]]
  def updateLastTextCheckAt(amendmentId: Long): F[Unit]                 // per L1 — only called on success path
}
```

> **Extends `EntityRepository[F, AmendmentDO]`** — this enables `PlaceholderCreator` (Component 3 §3.6) to create placeholder amendments. **The votes-pipeline calls `upsertPlaceholder` directly** (see §7.4) when a roll call references an amendment not yet in the database. The bill-summary-pipeline does **not** call this — the `/summaries` endpoint returns no amendment references, so summary processing has no occasion to create amendment placeholders.

**`upsert`:**
- Uses `UpsertHelper.upsertFragment` with `Tables.Amendments`
- Conflict column: `natural_key` (UNIQUE) — surrogate `id` is auto-generated on insert
- Updates all non-key, non-audit columns on conflict
- All Congress.gov-sourced date columns (`update_date`, `submitted_date`, `latest_action_date`) flow through **directly from the DTO** — never coalesced with `NOW()` or any RepCheck clock. See §Date Semantics below. (No `proposed_date` — Congress.gov API has no such field.)
- Sets `updated_at = NOW()` on conflict (RepCheck-internal audit column only)
- Leaves `created_at` untouched on conflict (set by DB `DEFAULT NOW()` on first insert and never overwritten)
- **RETURNING `*`** — returns the full persisted DO including the surrogate `id`. Mirrors `DoobieVoteRepository.upsert` shape.

**`upsertPlaceholder`** — mirrors the precedent set by `BillRepository.upsertPlaceholder` in [bills-common](../../../../bills-common/src/main/scala/repcheck/ingestion/bills/common/persistence/BillRepository.scala) (`F[Unit]`, `ON CONFLICT DO NOTHING`). Caller pairs it with `findByNaturalKey` to get the surrogate id — same shape as votes-pipeline's [`BillLookup.forContext`](../../../../votes-pipeline/src/main/scala/repcheck/ingestion/votes/pipeline/BillLookup.scala):

- Parses `naturalKey` (`{congress}-{amendmentType}-{number}`) into components; raises `InvalidAmendmentNaturalKey` if malformed.
- Idempotent insert:
  ```sql
  INSERT INTO amendments (natural_key, congress, amendment_type, number, chamber)
  VALUES (?, ?, ?::amendment_type_enum, ?, ?::chamber_type)
  ON CONFLICT (natural_key) DO NOTHING
  ```
- **`chamber` is always populated even on placeholders** (per L9). Derived from `amendmentType`: `HAMDT → House`, `SAMDT/SUAMDT → Senate`. The mapping is total — every placeholder has a non-NULL chamber. Callers reach this path via either: (a) the §7.4 votes-pipeline, where `amendmentType` is parsed from the upstream document type before this method is called; (b) §7.3 sub-amendment recursion, where `amendmentType` is parsed from the natural key. Both sources unambiguously imply chamber.
- All **other** columns are NULL on initial INSERT — `update_date`, `submitted_date`, `latest_action_date`, `description`, `purpose`, `sponsor_member_id`, `bill_id`, `parent_amendment_id`. Those NULLs are what mark the row as a placeholder for §7.3's stage-1a hydration check.
- Returns `F[Unit]`. Caller (§7.3, §7.4) reads back the surrogate id via `findByNaturalKey(naturalKey).map(_.map(_.amendmentId))`. The 2-step pattern is the codebase precedent — the marginal extra SELECT is negligible at expected volumes. Safe under concurrent ingestion — Postgres serializes the conflict resolution.

> **Why `DO NOTHING`, not `DO UPDATE`:** placeholders must never overwrite existing data. A real fully-hydrated amendment row that gets a redundant placeholder upsert from votes-pipeline or sub-amendment recursion must remain untouched. `DO NOTHING` enforces that invariant at the SQL layer; `DO UPDATE` would risk clobbering values if the no-op SET were ever changed in a future edit.

> **Why a placeholder has `update_date = NULL` rather than `update_date = NOW()`:** if a placeholder were stamped with the local clock, the next amendments-pipeline run's `ChangeDetector` would compare a Congress.gov `updateDate` (from the API) against a RepCheck wall-clock value, and a placeholder created seconds before the next pipeline run could appear "newer" than the real Congress.gov data. NULL `update_date` guarantees the first hydration run treats the placeholder as `New` and overwrites it. This is the same reason the diff-comparison rule (§Date Semantics) bans NOW() from any DTO-sourced column.

> **Placeholder detection is broader than `update_date IS NULL`** (per §7.3 stage-1a): the change detector treats *any* NULL in the required-field set `{congress, amendmentType, number, chamber, updateDate}` as a placeholder. This handles three scenarios uniformly: a clean votes-pipeline placeholder (only natural-key components populated), a partial row from a crashed prior run (mixed NULLs), and any future placeholder source that populates a different subset. The required-field set covers exactly those columns the Congress.gov API guarantees to populate on every real amendment — optional fields (`description`, `sponsorBioguideId`, `billId`, etc.) are excluded because they can be legitimately NULL in fully-hydrated rows.

**`findById`:**
- Simple SELECT by `id` (surrogate). Used internally for `upsertPlaceholder` round-trip.

**`findByNaturalKey`:**
- Simple SELECT by `natural_key`
- Returns `Option[AmendmentDO]` — `None` if not found
- Used by `AmendmentProcessor` to fetch stored amendment for `ChangeDetector` comparison (the change detector keys on natural_key from the API response)

**`findByBillId`:**
- SELECT by `bill_id` (surrogate Long, per Q3)
- Returns all amendments associated with a bill
- Used by Component 11 §11.12 stance materializer (when materializing a bill, it scans for the bill's amendments)

**`findByCongress`:**
- SELECT by `congress`
- Returns all amendments for a given congress
- Ordered by `id`

**No `computeEffectiveBillId` / `updateEffectiveBillId` / `findByEffectiveBillId`** — per 2026-05-05 design revision, there is no separate `effective_bill_id` column. `bill_id` is always populated with the resolved ancestor bill at ingest time (the §7.3 processor walks the parent chain inline). Querying "all amendments touching bill X" is just `findByBillId(X)`. Querying "direct top-level amendments to X" is `findByBillId(X) WHERE parent_amendment_id IS NULL`.

**`insertIfNotExists`:**
- `INSERT ... ON CONFLICT DO NOTHING` with the provided `AmendmentDO`
- Inherited from `EntityRepository` — used by `PlaceholderCreator` pattern
- No-op if amendment already exists

### `AmendmentDO` Field Mapping

Per Component 1 §1.2, `AmendmentDO` maps to the `amendments` table:

| DO Field | Column | Type | Notes |
|----------|--------|------|-------|
| `amendmentId` | `id` | Long (PK, BIGSERIAL) | **Surrogate id**, per Q3 (system-wide convention). Auto-generated by DB on insert |
| `naturalKey` | `natural_key` | String (UNIQUE) | `{congress}-{amendmentType}-{number}` — used by `upsertPlaceholder` and natural-key joins from votes-pipeline |
| `congress` | `congress` | Int | |
| `amendmentType` | `amendment_type` | Option[`amendment_type_enum`] | `'HAMDT'`, `'SAMDT'`, or `'SUAMDT'`. Postgres enum; Doobie maps via `DoobieEnumInstances` |
| `number` | `number` | String | Amendment number within congress |
| `billId` | `bill_id` | Option[Long] | **Surrogate FK** → `bills(id)`. **Always the resolved ancestor bill** (set inline by §7.3's recursive parent-resolution flow). NULL only for legitimate orphans (treaty / procedural amendments where no bill chain exists). |
| `parentAmendmentId` | `parent_amendment_id` | Option[Long] | **Surrogate FK** → `amendments(id)` (self-reference). Populated when DTO has `amendedAmendment` — the amendment is a sub-amendment of another amendment. |
| `chamber` | `chamber` | `chamber_enum` (NOT NULL) | `'House'` or `'Senate'`. **Always populated** (per L9) — derived from `amendmentType` (`HAMDT → House`, `SAMDT/SUAMDT → Senate`), which itself is parsed from the natural key on every code path that creates amendment rows. The previous `Option`-typed column reflected an over-cautious null-tolerance; it's tightened to NOT NULL because the upstream sources guarantee this. |
| `description` | `description` | Option[String] | House amendments only per upstream — Senate omits this |
| `purpose` | `purpose` | Option[String] | |
| `sponsorMemberId` | `sponsor_member_id` | Option[Long] | **Surrogate FK** → `members(id)`. Resolved from `detail.sponsors[0].bioguideId` via `memberRepo.upsertPlaceholder` + `findByBioguideId` (per §7.3 step 2). Some amendments have no identified sponsor |
| `submittedDate` | `submitted_date` | Option[LocalDate] | **DTO-sourced** — recorded directly from Congress.gov, never replaced by NOW(). LocalDate (date-only, no timezone). (No `proposedDate` — Congress.gov API has no such field; dropped 2026-05-05 review.) |
| `latestActionDate` | `latest_action_date` | Option[LocalDate] | **DTO-sourced.** From `latestAction.actionDate` |
| `latestActionTime` | `latest_action_time` | Option[String] | **DTO-sourced.** From `latestAction.actionTime`. Stored as string (`HH:mm:ss`) — Congress.gov returns date and time separately, combining requires assumed timezone we don't have. Added in shared-models 0.1.40 |
| `latestActionText` | `latest_action_text` | Option[String] | DTO-sourced |
| `updateDate` | `update_date` | Option[Instant] | **DTO-sourced.** Nullable so `upsertPlaceholder` can leave it unset until hydration. Used by `ChangeDetector` |
| `apiUrl` | `api_url` | Option[String] | Congress.gov API URL — **use the `url` field from the API response verbatim**, e.g. `https://api.congress.gov/v3/amendment/117/samdt/2137?format=json`. Do not synthesize |
| `lastTextCheckAt` | `last_text_check_at` | Option[Instant] | **RepCheck-internal audit.** When §7.5 last **successfully** completed text check for this row (per L1 — only set on success path). NULL until first successful check. Excluded from `ChangeDetector`. Added in shared-models 0.1.40 |

> **Per S2 simplification — no `text_versions_count` column.** Earlier drafts had a denormalized counter mirroring upstream `pagination.count`. That counter could drift from the actual ingested-version count and added a write surface for §7.5 to maintain. Dropped — when a caller needs the count, they query `count(*) FROM amendment_text_versions WHERE amendment_id = ?` directly.
| `createdAt` | `created_at` | Instant | **RepCheck-internal audit.** DB `DEFAULT NOW()` on first insert; never overwritten. Excluded from `ChangeDetector` |
| `updatedAt` | `updated_at` | Instant | **RepCheck-internal audit.** DB `DEFAULT NOW()`; explicitly set to `NOW()` on every `upsert` conflict. Excluded from `ChangeDetector` |

### Fields Deliberately Not Stored (MVP)

The detail endpoint returns several additional fields per [LoC AmendmentEndpoint.md](https://github.com/LibraryOfCongress/api.congress.gov/blob/main/Documentation/AmendmentEndpoint.md). The DO and table omit them in initial scope:

| Upstream field | Reason for omission | Future treatment |
|----------------|---------------------|------------------|
| `cosponsors` (count + url) | Cosponsor data is not part of MVP per §7.1; would require a separate join table | Add `amendment_cosponsors` table mirroring `bill_cosponsors` if/when needed |
| `actions` (count + url) | Actions timeline not consumed downstream; `latestAction*` fields capture what's needed | Add `amendment_actions` table if downstream needs the full action history |
| `textVersions` (count + url, 117th forward) | Amendment text not part of MVP per §7.1 | Route through `bill-text-pipeline` if/when needed |
| `amendedAmendment` | Sub-amendments (amendment-amends-amendment) — edge case | Add `amends_amendment_id: Option[String]` self-FK if needed |
| `amendedTreaty` | Treaty-amending amendments — rare edge case | Add `amended_treaty_id: Option[String]` if treaty ingestion ever lands |
| `onBehalfOfSponsor` | Manager amendments where the formal sponsor differs from the offerer — rare | Add `on_behalf_of_bioguide_id: Option[String]` if downstream needs the distinction |
| `notes` | Free-text annotations — no current consumer | Skip indefinitely unless explicit need surfaces |
| `amendmentsToAmendment` (count + url) | Inverse of `amendedAmendment` — derivable via self-join once `amendedAmendment` is stored | Skip; compute at query time |

**Rationale:** every omission represents a fan-out into either a child table or a JSONB column. The repo convention bans JSONB for structured data, so each addition is a new table — meaningful schema cost. MVP keeps the table to one row per amendment with denormalized fields. Add per concrete need.

### Date Semantics

A strict separation between two clocks lives in this table:

| Clock | Columns | Source | Mutable? |
|-------|---------|--------|----------|
| **Congress.gov** | `update_date`, `submitted_date`, `latest_action_date` | DTO from API | Replaced on every `upsert` from the latest detail response — **never** replaced with `NOW()` or any local clock |
| **RepCheck-internal** | `created_at`, `updated_at` | Postgres `DEFAULT NOW()` and explicit `NOW()` on update | `created_at` immutable after first insert; `updated_at` advanced on every conflict update |

**Critical invariant:** `ChangeDetector` (§7.3) compares **only** Congress.gov-sourced columns. Mixing clocks would corrupt diff detection — every upsert would tick `updated_at`, the diff would always show a change, and the pipeline would fail to short-circuit on unchanged amendments. Internal audit columns are excluded from the diff specifically so the change detector remains driven by upstream truth.

This is why `upsertPlaceholder` leaves `update_date` NULL rather than stamping it with `NOW()` — see the §upsertPlaceholder note above.

### Error Types

```
final case class AmendmentUpsertFailed(
  amendmentId: String,
  detail: String,
  cause: Option[Throwable] = None
) extends Exception(s"Failed to upsert amendment $amendmentId: $detail", cause.orNull)

final case class InvalidAmendmentNaturalKey(
  naturalKey: String,
  detail: String
) extends Exception(s"Invalid amendment natural key '$naturalKey': $detail")
```

`InvalidAmendmentNaturalKey` is raised by `upsertPlaceholder` when the supplied string doesn't parse into the canonical `{congress}-{amendmentType}-{number}` shape. Mirrors `InvalidBillNaturalKey` from `bills-common`.

## Acceptance Criteria

| Criterion | Test |
|-----------|------|
| `upsert` inserts new amendment | Insert → `findByAmendmentId` → returns amendment with all fields |
| `upsert` updates existing amendment on conflict | Insert → upsert with changed description → verify description updated |
| `upsert` does not create duplicate rows | Upsert same `amendmentId` twice → exactly 1 row |
| `upsert` sets `updated_at` on conflict | Upsert existing → `updated_at` changed to current NOW() |
| `upsert` does NOT overwrite `created_at` on conflict | Insert at T0 → upsert at T1 → `created_at` still T0 |
| `upsert` records DTO `update_date` verbatim, never NOW() | DTO `updateDate = 2021-08-08T12:00:00Z` → DB `update_date = 2021-08-08T12:00:00Z` exactly (millisecond match), regardless of clock at insertion time |
| `upsert` records DTO `submitted_date` verbatim | DTO value preserved byte-for-byte; not coalesced or rounded |
| `upsert` records DTO `latest_action_date` verbatim | DTO value preserved byte-for-byte |
| `upsertPlaceholder` parses valid natural key and inserts row | `"117-SAMDT-2137"` → row inserted with surrogate `id`, `natural_key="117-SAMDT-2137"`, `congress=117`, `amendmentType=SAMDT`, `number="2137"`, `chamber=Senate`, all other columns NULL |
| `upsertPlaceholder` returns the surrogate id | Insert new placeholder → returned Long matches the row's `id` column |
| `upsertPlaceholder` returns existing id when row already exists | Pre-existing row → call again → returns same surrogate id, row unchanged |
| `upsertPlaceholder` derives chamber from amendment type | HAMDT → House; SAMDT/SUAMDT → Senate |
| `upsertPlaceholder` is no-op when row exists with full data | Real amendment present → call placeholder → row unchanged (richer data preserved), returns surrogate id |
| `upsertPlaceholder` raises `InvalidAmendmentNaturalKey` on malformed input | `"not-a-key"`, `"117-FOO-1"`, empty string → exception |
| `upsertPlaceholder` leaves `update_date` NULL | Placeholder row → `update_date IS NULL` (so first hydration run treats as `New`) |
| `findCandidatesForTextCheck` excludes pre-117th and SUAMDT | Insert mix of 116/117/118 + SAMDT/HAMDT/SUAMDT → returns only 117+118 SAMDT/HAMDT |
| `findCandidatesForTextCheck` selects NULL or stale `last_text_check_at` | `staleAfter=4h`: rows with NULL or `last_text_check_at < NOW()-4h` returned |
| `findCandidatesForTextCheck` parameterizes `staleAfter` (no SQL injection risk) | Pass a string param `"4 hours"` and verify it's bound as a parameter, not interpolated into SQL string |
| `updateLastTextCheckAt` sets timestamp on success path only | Call `updateLastTextCheckAt(id)` → row's `last_text_check_at = NOW()`. **Failure path test:** §7.5 processAmendment fails → `updateLastTextCheckAt` not called → `last_text_check_at` unchanged (per L1) |
| **`findByNaturalKeys` (per P2 batch helper) returns map keyed by natural key** | Insert 3 rows. Call `findByNaturalKeys(List(nk1, nk2, nk_missing))` → returns `Map(nk1 -> row1, nk2 -> row2)` (missing key omitted, not NULL-mapped) |
| **`findByNaturalKeys` issues exactly one SQL query** | Spy DB asserts: 1 SELECT statement issued for N input keys, regardless of N |
| **`findByNaturalKeys` empty input returns empty map** | Call with `List.empty` → returns `Map.empty`; no SQL issued |
| `findByAmendmentId` returns `None` for missing amendment | Unknown ID → `None` |
| `findByAmendmentId` returns stored amendment with all fields | Insert → find → all fields match |
| `findByBillId` returns amendments for a bill | Insert 3 amendments for bill X → `findByBillId(X)` → returns 3 |
| `findByBillId` returns empty list when no amendments | Unknown bill → empty list |
| `findByCongress` returns amendments for a congress | Insert amendments for congress 117 and 118 → `findByCongress(117)` → returns only 117 |
| `insertIfNotExists` inserts when missing | New amendment → inserted |
| `insertIfNotExists` is no-op when exists | Existing amendment → row unchanged |
| `insertIfNotExists` does not overwrite richer data | Full amendment exists → `insertIfNotExists` with placeholder → full data preserved |
| FK constraint on `bill_id` requires bill to exist | Amendment with unknown `bill_id` → FK violation |
| FK constraint on `sponsor_bioguide_id` requires member to exist | Amendment with unknown sponsor → FK violation |
| `bill_id = None` is valid (standalone amendment) | Insert amendment without bill → succeeds |
| `sponsor_bioguide_id = None` is valid | Insert amendment without sponsor → succeeds |
| All SQL uses `Tables.*` constants | No hardcoded table/column name strings |
| **`upsertPlaceholder` is single-roundtrip (per S5)** | Spy DB asserts: 1 SQL statement issued per call (INSERT…ON CONFLICT…RETURNING id), not 2 (no separate SELECT) |
| **`chamber` is always populated, even on placeholders (per L9)** | Insert placeholder via `upsertPlaceholder("117-SAMDT-2137")` → row's `chamber = 'Senate'` (NOT NULL); `upsertPlaceholder("117-HAMDT-100")` → `chamber = 'House'` |
| **NOT NULL constraint on `chamber`** | Attempt to INSERT row with `chamber = NULL` → DB rejects with NOT NULL violation |
| **No `text_versions_count` column on schema (per S2)** | `\d amendments` shows no `text_versions_count` column; existing code that queries it would fail to compile |
| **Concurrent `upsertPlaceholder` calls don't duplicate rows** | Spawn 50 fibers calling `upsertPlaceholder(sameKey)` simultaneously → exactly 1 row exists; all 50 returned the same surrogate id |
| **Concurrent `upsert` of conflicting full data** | Spawn 2 fibers calling `upsert` on the same natural_key with different DTO values → exactly 1 row exists; one fiber's data wins (last-writer-wins via Postgres conflict resolution); no duplicate rows |
| **`findByBillId` returns only rows whose ancestor resolved to that bill** | Insert orphan amendment (`bill_id = NULL`) → not returned by `findByBillId(X)`. Insert top-level amendment with `bill_id = X` and sub-amendment whose ancestor resolves to `X` → both returned. |
| **Orphan amendments excluded from downstream scoring (per L8)** | `findByBillId(X)` SQL: `WHERE bill_id = ?` — `bill_id IS NULL` rows are not returned. Document this in L8 contract: future scoring/analysis pipelines polling via `findByBillId` will SKIP treaty amendments, procedural amendments, and any amendment whose chain didn't resolve to a bill. **This is intentional** — those amendments can't be attributed to a bill's score. |
