# 7.6 Amendment Text Pipeline

> Part of [Component 7 — Amendments Pipeline](../07-AMENDMENTS-PIPELINE.md)

## Overview

Cloud Run Service (long-running Pub/Sub subscriber). Consumes `amendment.text.available` events (emitted by §7.5), downloads the amendment text via `api.govinfo.gov` (CREC mirror), extracts to plain text, chunks, embeds, and persists. **No completion event is emitted** — downstream pipelines (analysis, scoring) discover ready amendments by polling `amendment_text_versions WHERE fetched_at IS NOT NULL`, mirroring the bill-side pattern after that side's own ingestion-event removal.

**Implementation strategy mirrors `bill-text-pipeline` byte-for-byte.** Same chunker (`TextChunker` — character-based, `maxChunkChars=12000`, no overlap, format-agnostic), same embedder (`OllamaEmbeddingService` — HTTP POST to local Ollama, model `bill-text-embedding` which is a tuned `qwen3-embedding:0.6b`, 1024-dim output vectors), same crash semantics (NULL `fetched_at` while in-flight, orphan-chunk cleanup on retry, `markFetched` UPDATE on completion). All shared code lives in `text-extraction-common` after [P7.4](PRODUCTION_TASKS.md#p74).

> **Verified ingestion path (P7.1 result, 2026-05-03):** the `/amendment/.../text` endpoint returns format URLs of shape `https://www.congress.gov/{congress}/crec/{yyyy}/{mm}/{dd}/{vol}/{issue}/[modified/]CREC-{yyyy-mm-dd}-pt{N}-Pg{Section}{-N}.{ext}`. **The same content is mirrored on `api.govinfo.gov` under the CREC collection** — verified `HEAD https://api.govinfo.gov/packages/CREC-2021-08-01/granules/CREC-2021-08-01-pt1-PgS5255/htm?api_key=$GOVINFO_API_KEY` returns `200 OK, Content-Type: text/html, Content-Length: 3MB`, no Cloudflare interaction. Govinfo rate limit `36000/hour` per the `X-Ratelimit-Limit` response header.
>
> **Strategy:** mirror the existing [`GovInfoUrlRewriter`](../../../../bill-text-pipeline/src/main/scala/repcheck/ingestion/bills/text/download/GovInfoUrlRewriter.scala) approach for bills. Build a `CrecGovInfoUrlRewriter` that parses Congress.gov CREC URLs into `(packageId, granuleId, formatSuffix)` and rewrites to `api.govinfo.gov`. The Cloudflare-related elaborate strategy in earlier drafts (browser-shaped UA, retry-on-challenge, headless browser sidecar fallback, LoC allowlist outreach) is **not needed** — the api.govinfo.gov path is direct and authenticated via API key.

```
Pub/Sub: amendment.text.available
    |
    +-- amendment-text-pipeline (subscriber)
          |
          +-- For each event (parEvalMap):
                +-- Single-statement upsert (per S4):
                |     INSERT ... ON CONFLICT DO UPDATE ... RETURNING id, inserted, alreadyComplete
                |     - alreadyComplete=true (existing row with newer/equal published_date) -> Skipped, ACK
                |     - inserted OR re-submission per L6 (published_date newer) -> proceed; fetched_at NULL
                +-- DELETE orphan chunks for this version_id (idempotent)
                +-- CrecGovInfoUrlRewriter.rewrite(event.url) -> api.govinfo.gov URL
                +-- Streaming download from rewritten URL (HTML or PDF)
                |     - HTML: bytes -> CrecHtmlExtractor -> plain text stream
                |     - PDF:  bytes -> PdfStreamExtractor (spool to temp file) -> plain text stream
                +-- TextChunker.chunkPipe(maxChunkChars=12000) -> chunk stream
                +-- OllamaEmbeddingService (qwen3-embedding:0.6b, 1024-dim) -> per-chunk INSERT
                |     [bounded by OLLAMA_EMBED_QUEUE_BYTES = 1.2MB per P8]
                +-- UPDATE amendment_text_versions SET fetched_at = NOW(), text_length = $bytes
                +-- ACK message  (NO event emitted — readiness is fetched_at IS NOT NULL)
```

## Classes

### `CrecGovInfoUrlRewriter`

Mirror of [`GovInfoUrlRewriter`](../../../../bill-text-pipeline/src/main/scala/repcheck/ingestion/bills/text/download/GovInfoUrlRewriter.scala) but for the CREC collection. Pure stateless object.

```
private[download] object CrecGovInfoUrlRewriter {

  // Captures: (packageId="CREC-2021-08-01", granuleId="CREC-2021-08-01-pt1-PgS5255", formatSuffix="htm"|"pdf")
  private val CongressGovCrecUrlPattern: Regex =
    """^https?://(?:www\.)?congress\.gov/\d+/crec/\d+/\d+/\d+/\d+/\d+/(?:modified/)?(CREC-\d{4}-\d{2}-\d{2})(-pt\d+-Pg[A-Za-z0-9-]+)\.(htm|pdf)(?:\?.*)?$""".r

  def parseCongressGovCrecUrl(originalUrl: String): Option[(String, String, String)] =
    CongressGovCrecUrlPattern.findFirstMatchIn(originalUrl).map { m =>
      val pkg = m.group(1)               // "CREC-2021-08-01"
      val granuleSuffix = m.group(2)     // "-pt1-PgS5255"
      val granule = pkg + granuleSuffix  // "CREC-2021-08-01-pt1-PgS5255"
      val ext = m.group(3)               // "htm" | "pdf"
      (pkg, granule, ext)
    }

  // Build api.govinfo.gov package URL — API key appended at request time, not embedded
  def toGovInfoUrl(packageId: String, granuleId: String, formatSuffix: String, baseUrl: String): String =
    s"${baseUrl.stripSuffix("/")}/packages/$packageId/granules/$granuleId/$formatSuffix"
}
```

| Function | Signature | Behavior |
|---|---|---|
| `parseCongressGovCrecUrl` | `(originalUrl: String) => Option[(String, String, String)]` | Match against the regex above. Returns `(packageId, granuleId, formatSuffix)` for the three URL pattern variants observed in production (with and without the `modified/` segment, with various page suffixes including `PgS5255`, `PgS1044-4`, etc.). Returns `None` for URLs that don't match — caller falls back to the original URL (downloads via www.congress.gov, accepting Cloudflare risk for the unlikely long-tail). |
| `toGovInfoUrl` | `(packageId, granuleId, formatSuffix, baseUrl) => String` | Compose the final api.govinfo.gov path. Pure — no IO. API key appended by the downloader at request time via `Uri.withQueryParam("api_key", ...)`. |

### `AmendmentTextDownloadErrorClassifier`

Standard shape — no Cloudflare special-casing. Mirrors the existing [`BillSummariesApiErrorClassifier`](../../../../bill-summary-pipeline/src/main/scala/repcheck/ingestion/bills/summary/errors/BillSummariesApiErrorClassifier.scala) exactly:

```
override def classify(error: Throwable): ErrorClass = error match {
  case e if isTransientNetworkError(e) => ErrorClass.Transient    // EmberException / IOException via cause-chain walk
  case _ => super.classify(error)                                  // 429/500/502/503/504 Transient; rest Systemic
}
```

`api.govinfo.gov` returns HTTP 429 when `X-Ratelimit-Remaining` reaches 0 — already handled as Transient by the base classifier. Real 403/401 from govinfo means the API key is invalid — Systemic, halt the run, alert the operator.

### `AmendmentTextExtractor[F[_]: Async]`

Format-dispatched streaming extractor. Two formats only — HTML and PDF. Per Q18 of planning, **HTML uses a NEW `CrecHtmlExtractor` purpose-built for Congressional Record markup** (the `BillTextExtractor.HtmlStreamExtractor` targets cleaner `BILLS-*` HTML and would leave CREC noise in extracted chunks). PDF reuses `PdfStreamExtractor` from `text-extraction-common` since PDF extraction is content-format-agnostic.

| Function | Signature | Behavior |
|---|---|---|
| `extract` | `(bytes: Stream[F, Byte], formatType: String) => Stream[F, String]` | Dispatch on `formatType`: `"HTML"` → `CrecHtmlExtractor.extract(bytes)` (new — see below); `"PDF"` → `PdfStreamExtractor.extract(bytes)` (shared). |

### `CrecHtmlExtractor` — NEW (per Q18)

Lives alongside `HtmlStreamExtractor` in `text-extraction-common`. **Shares the streaming HTML-parser harness** (FS2-driven, jsoup or similar) with `HtmlStreamExtractor` — only the noise-stripping rules differ. Common base trait:

```scala
trait HtmlStreamExtractorBase[F[_]] {
  protected def shouldKeepNode(node: Element): Boolean
  protected def transformText(raw: String): String
  def extract(bytes: Stream[F, Byte]): Stream[F, String]
}
```

Two concrete implementations:
- `HtmlStreamExtractor` — keeps everything, light text normalization (existing for bills)
- `CrecHtmlExtractor` — drops CREC-specific noise

**Encoding + entity handling** (per Q45 + Q46):
- **Charset: UTF-8 only.** `Charset.forName("UTF-8")` for byte-stream decoding. Govinfo CREC HTML is documented as UTF-8 for modern (post-2009) records and assumed acceptable for older too. Decode errors surface as warnings; if a real Latin-1 document trips the decoder, that's a bug to investigate (not a silent fallback).
- **HTML entities decoded to literal characters** before chunking: `&mdash;` → `—`, `&sect;` → `§`, `&deg;` → `°`, `&amp;` → `&`, etc. Use jsoup or a library that normalizes during parse. Embeddings work better with literal characters than entity escapes.

**CREC-specific noise rules** (in `CrecHtmlExtractor.shouldKeepNode` and `transformText`):

| Rule | Example | Action |
|---|---|---|
| Running header "CONGRESSIONAL RECORD — SENATE" / "—HOUSE" | `<div class="hd">CONGRESSIONAL RECORD — SENATE August 1, 2021</div>` | Drop the entire header div |
| Page-number footer "Pg S5255" | Standalone bottom-of-page page-number text | Drop |
| Time-of-day annotations | `[Time: 10:30 a.m.]` | Drop or strip the bracket annotation |
| Speaker tags | `<i>Mr. SCHUMER.</i>` | **Keep** — speaker context is part of the amendment's textual evidence |
| Page-break separators | `<hr/>` between pages | Drop |
| Section markers within amendment text | `Section 1.`, `(a)`, `(b)(2)` | Keep — these are the amendment's structural skeleton |
| In-text page references like `[[Page S5256]]` | Inline page markers | Drop the bracketed reference, keep surrounding text |

Behavior is empirical — first implementation should be conservative (keep more than less), then tighten via embeddings-quality observation. Document an explicit "if extraction quality issues surface, the noise rules are the first place to look."

**Shared streaming harness**: both extractors handle multi-MB bodies without buffering the full HTML in memory. Stream parser → element-level filtering → text accumulation in a fixed-size FS2 chunk window. PerCRoss-extractor re-use of the parser machinery means CREC adoption is mostly: define the noise rules, plug into the harness.

> **No XML extractor for amendments** — upstream doesn't publish Formatted XML granules for amendments. If that ever changes, add a third dispatch arm.

### Chunking — `TextChunker` (shared from `text-extraction-common`)

**Reuses the bills-pipeline chunker directly** — chunking is content-agnostic, the same algorithm works for any plain text. After [P7.4](PRODUCTION_TASKS.md#p74) the existing `BillTextChunker` (currently in `bill-text-pipeline/src/main/scala/.../chunking/BillTextChunker.scala`) is renamed to `TextChunker` and moved to `text-extraction-common`. Both pipelines depend on it.

| Constant | Value | Source |
|---|---|---|
| `maxChunkChars` | `12000` (default — operator-tunable via `OLLAMA_MAX_CHUNK_CHARS`) | bills `application.conf` |
| Basis | Character-based (UTF-16 code units via `String.length`), NOT token-based | bills convention |
| Overlap | None — fixed sliding window with no overlap | bills convention |
| Streaming | fs2 `Pull`-based — heap bounded by `maxChunkChars + one fragment` regardless of document size | bills `chunkPipe[F[_]]` |
| Format awareness | Format-agnostic — receives `Stream[F, String]` of pre-extracted semantic fragments from the format-specific extractor (HTML or PDF) | shared |

The `chunkPipe[F[_]: Async](maxChunkChars: Int): Pipe[F, String, String]` entry point is unchanged.

### Embedder — `OllamaEmbeddingService` (shared from `text-extraction-common`)

**Reuses the bills-pipeline embedder directly.** After [P7.4](PRODUCTION_TASKS.md#p74), `OllamaEmbeddingService` (currently in `bill-text-pipeline/src/main/scala/.../embedding/`) and `CrossBillEmbedder` (renamed to `CrossEntityEmbedder` or kept generic-typed) move to `text-extraction-common`.

| Concern | Value | Source |
|---|---|---|
| Transport | HTTP POST to `${OLLAMA_BASE_URL:-http://localhost:11434}/api/embed` | bills convention |
| Model name | `bill-text-embedding` — a tuned variant of `qwen3-embedding:0.6b` | bills `application.conf:72` |
| Output dimension | **1024** (validated in `EmbeddingConfig`) | bills `application.conf:76` |
| Schema column | `vector(1024)` per pgvector — same dimension as `raw_bill_text.embedding` | bills migration 028 |
| Batching | 50 chunks per batch, 1s timeout (matches bills — per directive, do not lower for amendments) | bills `application.conf:95+` |
| **Queue back-pressure (per P8)** | **Bounded by `OLLAMA_EMBED_QUEUE_BYTES = 1.2MB`** (≈ `maxChunkChars × 100` worth of in-flight chunks). Producer blocks on `enqueue` when the bound is reached. Prevents heap blowup on a 50MB amendment while still saturating Ollama. | NEW — replaces unbounded queue from earlier draft |
| Persistence cast | Doobie SQL `?::vector` for pgvector binding | bills `DoobieRawBillTextRepository` |

> **Why a byte-bound, not a chunk-count bound** (per P8): chunk sizes vary wildly. A bound of "500 chunks" works fine for typical amendments but a single 50MB substitute amendment could put 4000+ chunks at `maxChunkChars=12000` in the queue — heap pressure. A byte bound (`sum-of-chunk-bytes <= queueBytes`) is content-aware. The producer (chunker) calls `queue.tryOffer` with semantic blocking when the byte sum hits the limit; the consumer (embedder) drains in 50-chunk batches.

> **Why share the model with bills:** keeping bills and amendments on the same embedding model means a single inference deployment, consistent semantic-similarity comparisons across bills and amendments (useful for analysis/scoring later), and no second model to maintain. The model-name constant lives in shared config.

### `AmendmentTextProcessor[F[_]: Async]`

The pipeline body. Constructor: `(downloader, amendmentRepository, amendmentTextVersionRepository, amendmentTextChunkRepository, embedder, embeddingConfig, eventPublisher, xa, logger, extractText)`.

| Function | Signature | Behavior |
|---|---|---|
| `processEvent` | `(event: AmendmentTextAvailableEvent) => F[ProcessingResult]` | Mirror of `BillTextProcessor.processEvent`. Per S4: `isAlreadyProcessed` is folded into the INSERT (single roundtrip). Per L6: re-submission of an already-fetched (versionType, format) tuple with a newer `publishedDate` triggers a content refresh rather than being silently ignored. (1) **Single-statement upsert**: `INSERT INTO amendment_text_versions (...) VALUES (...) ON CONFLICT (amendment_id, version_type_code, format_type) DO UPDATE SET source_url = EXCLUDED.source_url, download_url = EXCLUDED.download_url, published_date = EXCLUDED.published_date, fetched_at = NULL WHERE EXCLUDED.published_date > amendment_text_versions.published_date OR amendment_text_versions.fetched_at IS NULL RETURNING id, (xmax = 0) AS inserted, (fetched_at IS NOT NULL) AS already_complete` — returns `(versionId, inserted, alreadyComplete)`. The `WHERE` clause on the `DO UPDATE` ensures we only refresh when the upstream `publishedDate` is newer (real re-submission) OR when the existing row never completed (recovery). (2) If `alreadyComplete` is true (no rows updated → ON CONFLICT path returned nothing or returned the existing complete row): short-circuit to `Skipped("already-ingested")`, ACK message. (3) DELETE orphan chunks for this `version_id` (idempotent — no-op when row was just inserted). (4) Open streaming pipeline `downloader.streamBody → extractor.extract → TextChunker.chunkPipe → OllamaEmbeddingService → per-chunk INSERT`. (5) UPDATE `amendment_text_versions SET fetched_at = NOW(), text_length = ? WHERE id = ?`. (6) ACK Pub/Sub message. **No completion event is emitted** — `fetched_at IS NOT NULL` is the readiness signal. Returns `Succeeded`. |

Crash semantics identical to `BillTextProcessor`: a failure between version-row INSERT and `markFetched` UPDATE leaves the row with `fetched_at = NULL` and possibly partial chunks. Next event redelivery clears partial chunks and retries from scratch. Same trade-off — no long-held transaction during embedding.

## Schema additions

Two new tables, defined in `repcheck-db-migrations`. **Per Q3, both reference `amendments(id)` (surrogate BIGINT), not `amendments(natural_key)`.**

**Per L3:** amendment text version codes (`SUB`, `MOD`) get a **dedicated `amendment_text_version_code_type` enum**, NOT a co-mingled extension of the bill-side `text_version_code_type` enum. The bill enum is bill-shaped (`IH`, `EH`, `RH`, etc.); mixing amendment codes into it would be a misuse — same column type carrying two semantically distinct vocabularies.

```sql
-- Per L3 — separate enum from bill-side text_version_code_type.
-- Initial values match upstream Congress.gov API "type" field for amendment text versions.
CREATE TYPE amendment_text_version_code_type AS ENUM ('SUB', 'MOD');

CREATE TYPE amendment_format_type AS ENUM ('HTML', 'PDF');

CREATE TABLE amendment_text_versions (
  id                 BIGSERIAL PRIMARY KEY,
  amendment_id       BIGINT NOT NULL REFERENCES amendments(id) ON DELETE CASCADE,  -- surrogate FK
  version_type_code  amendment_text_version_code_type NOT NULL,  -- per L3: dedicated enum
  format_type        amendment_format_type NOT NULL,
  source_url         TEXT NOT NULL,                    -- original www.congress.gov URL from event
  download_url       TEXT NOT NULL,                    -- rewritten api.govinfo.gov URL actually used
  published_date     TIMESTAMPTZ,                      -- when upstream published this version; per L6, drives re-submission detection
  fetched_at         TIMESTAMPTZ,                      -- NULL = in-flight, crashed, or refreshing per L6
  text_length        BIGINT,                           -- bytes of extracted plain text
  created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (amendment_id, version_type_code, format_type)
);

CREATE INDEX amendment_text_versions_amendment_id_idx ON amendment_text_versions(amendment_id);
CREATE INDEX amendment_text_versions_pending_idx ON amendment_text_versions(amendment_id) WHERE fetched_at IS NULL;
CREATE INDEX amendment_text_versions_completed_idx ON amendment_text_versions(amendment_id) WHERE fetched_at IS NOT NULL;
-- The two partial indexes support: (1) §7.6 isAlreadyProcessed via the completed_idx; (2) downstream consumers polling
-- "newly-ready" amendments via the completed_idx; (3) operator queries for stuck/in-flight rows via the pending_idx.

CREATE TABLE amendment_text_chunks (
  id          BIGSERIAL PRIMARY KEY,
  version_id  BIGINT NOT NULL REFERENCES amendment_text_versions(id) ON DELETE CASCADE,
  chunk_index INTEGER NOT NULL,
  text        TEXT NOT NULL,
  embedding   vector(1024) NOT NULL,                   -- pgvector, qwen3-embedding:0.6b (matches bills `raw_bill_text.embedding`)
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (version_id, chunk_index)
);

-- Per P4 — HNSW preferred over ivfflat: better recall/latency tradeoff for high-recall workloads,
-- recommended by pgvector authors. Cost: more index memory, longer build. Acceptable for the chunk volume.
CREATE INDEX amendment_text_chunks_embedding_idx
  ON amendment_text_chunks USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);
-- m = 16, ef_construction = 64 are pgvector's recommended starting defaults.
-- Tune ef_search at query time per recall/latency target (no schema change needed).
```

> **Re-submission semantics (per L6):** when upstream republishes a version (same `version_type_code` + `format_type` but new content), the §7.6 INSERT-ON-CONFLICT-DO-UPDATE path detects this via the `published_date > stored.published_date` clause and resets `fetched_at = NULL`. The next download flow clears orphan chunks (idempotent DELETE), re-streams text, re-chunks, re-embeds, and writes new chunks. Updates `text_length` to the new size and `fetched_at` to the new completion timestamp. Old chunks are gone after the orphan-cleanup DELETE — single source of truth per (version_type_code, format_type) tuple.

`Tables.AmendmentTextVersions` and `Tables.AmendmentTextChunks` constants added to `pipeline-models` (per [P7.5](PRODUCTION_TASKS.md#p75--pipeline-models-bump-for-amendment-events)).

**Why `download_url` is stored separately from `source_url`:** the source URL on the event is the Congress.gov CREC URL; the download URL is the rewritten api.govinfo.gov URL. Storing both lets us audit which path was used for each version and detect rewriter regressions when patterns shift.

## Backoff and observability

Standard `RetryConfig(maxRetries = 3, initialBackoff = 1s, multiplier = 2.0, maxBackoff = 30s)` — same as bill-text-pipeline's govinfo path. Govinfo's documented behavior is well-mannered (429 with rate-limit headers when overrunning, no surprise blocks), so aggressive backoff isn't needed.

Observability counters:

- `amendment_text_download_attempts_total{outcome="success|govinfo_429|govinfo_5xx|rewriter_miss|other"}` — Prometheus counter
- `amendment_text_download_govinfo_remaining` — gauge, sampled from `X-Ratelimit-Remaining` header on every response
- Alert: rate-limit remaining < 10% of `X-Ratelimit-Limit` (typically `36000`) within an hour
